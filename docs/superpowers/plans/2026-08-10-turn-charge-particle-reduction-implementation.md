# 回合蓄能粒子减量实施计划

日期：2026-08-10

状态：计划草案，待批准

对应设计：`docs/superpowers/specs/2026-08-10-turn-charge-particle-reduction-design.md`

## 1. 需求理解

普通回合蓄能当前在每个渲染帧为每个蓄能陀螺生成约 36 个吸附粒子。双方同步蓄能时，共享粒子池会迅速被填满，并在加色混合与 Bloom 下形成遮挡竞技场的大面积亮层。

本次采用已批准的 A1 方案：普通回合蓄能使用独立的轻量汇聚粒子，并按约 15 次/秒发射。目标是把可见粒子密度降低约 70%～75%，同时保留陀螺核心和能量环的蓄能辨识度。

本任务不改变战斗规则、回合时长、蓄能收益、确定性记录、红色屏幕氛围、全局 Bloom，以及碰撞、QTE、必杀、发射和出界特效。

## 2. 已确认假设

- 只调整 `activeTurnResolution` 中视觉动作等于 `charge` 的普通回合表现。
- 新粒子单批固定为 16 个，初始半径约为 `0.7～1.8`。
- 新粒子尺寸比现有普通吸附粒子缩小约 45%，生命周期约为 `0.20～0.35` 秒。
- 发射节奏基于渲染 `dt`，目标为约 15 次/秒。
- 长帧每帧最多发射一批，不追赶补发。
- 离开 `resolving` 状态后重置节流状态。
- 现有 `emitAbsorb()` 及其所有调用保持不变。
- 用户现有未跟踪素材、截图和 `referse/` 内容不暂存、不修改。

## 3. 成功标准

- 30Hz、60Hz、144Hz 下一秒内各触发约 15 批蓄能粒子。
- 长帧只触发一批，不产生追赶式爆发。
- 双方同步蓄能时形成两个紧凑、分离的汇聚能量场。
- 两个陀螺轮廓和竞技场中央地面纹理保持可见。
- 普通回合蓄能不再快速占满 600 个粒子的共享池。
- 现有 QTE、发射和其他吸附效果仍调用原 `emitAbsorb()`。
- 确定性战斗测试、单元测试、端到端测试、类型检查、正式构建和统一站点验证通过。
- 浏览器控制台没有新增错误。

## 4. 执行规则

- 每个逻辑步骤先写会失败的测试，再添加最小实现。
- 只有当前步骤验证成功后才进入下一步。
- 不为未来画质设置或其他粒子类型增加通用配置层。
- 不修改共享材质、全局 Bloom 或粒子池上限。
- 浏览器截图只作为视觉验收产物，不把随机粒子画面设为脆弱的像素级快照。
- 每次只暂存计划列出的文件，保留所有无关未跟踪内容。

## 【步骤 1】固定帧率无关的发射节奏

目标：

先用单元测试定义约 15 次/秒、长帧不追赶补发的视觉节流契约。

文件：

- 新增 `src/fx/turnChargeCadence.ts`
- 新增 `tests/unit/turn-charge-cadence.test.ts`

先写失败测试：

1. 以 30Hz、60Hz、144Hz 分别推进一秒，统计触发次数。
2. 断言三种帧率均触发约 15 次，并允许浮点边界下最多一次差异。
3. 以一个明显大于发射间隔的长帧推进，断言本帧只返回一次触发。
4. 先积累不足一次的时间，再以初始累计值重新推进，证明重置后不会继承旧进度。
5. 传入零或负 `dt` 时不触发，也不让累计时间倒退。

最小实现：

1. 定义唯一的普通回合蓄能间隔常量 `1 / 15`。
2. 提供一个纯函数，输入当前累计时间和本帧 `dt`，输出下一累计时间与是否发射。
3. 当累计时间达到间隔时只返回一次发射，并保留合理余数；不使用循环追赶多批。
4. 将无效或负 `dt` 按零处理。
5. 不引入类、事件系统、配置对象或新依赖。

验证：

```powershell
npx vitest run tests/unit/turn-charge-cadence.test.ts
npx tsc --noEmit
git diff --check
```

预期：新增节流测试通过，纯函数不依赖 Three.js、DOM 或战斗模拟。

推荐提交：`test(arena): define turn charge particle cadence`

## 【步骤 2】增加蓄能专用轻量汇聚粒子

目标：

在共享粒子池内增加一个窄用途发射入口，只降低普通回合蓄能的单批视觉重量。

文件：

- 修改 `src/fx/sparks.ts`

实施前检查：

1. 用 `rg` 固定现有 `emitAbsorb()` 的三个调用位置。
2. 确认 QTE 和发射蓄力仍需要原效果，不能改为新入口。

最小实现：

1. 增加 `emitTurnChargeAbsorb(x, z)`，不改变现有 `emitAbsorb(x, z, intensity)`。
2. 每次循环固定生成 16 个粒子。
3. 初始半径使用约 `0.7 + random * 1.1`。
4. 生成位置贴近所属陀螺，运动方向朝核心，并保留轻微切向旋流。
5. 粒子尺寸控制在能使平均尺寸比当前强度 `1.2` 的吸附粒子小约 45% 的范围。
6. 生命周期控制在 `0.20 + random * 0.15` 秒附近。
7. 继续复用现有 `spawnOne()`、共享缓冲区和材质，不增加第二套粒子池。

验证：

```powershell
rg -n "emitAbsorb|emitTurnChargeAbsorb" src/app/game.ts src/fx/sparks.ts
npx tsc --noEmit
git diff --check
```

预期：新入口编译成功，原 `emitAbsorb()` 的实现与既有调用未变化。

推荐提交：`feat(arena): add lightweight turn charge particles`

## 【步骤 3】把普通回合蓄能接入时间节流

目标：

只在普通回合 `resolving` 阶段按批准频率调用新粒子入口，并在其他状态清空累计时间。

文件：

- 修改 `src/app/game.ts`
- 如现有端到端类型声明需要同步，最小修改 `tests/e2e/deterministic-battle.spec.ts`

先写失败验证：

1. 运行步骤 1 的节流测试，证明纯逻辑已固定。
2. 使用现有 QA 接口触发普通蓄能回合，确认修改前仍由逐帧 `emitAbsorb()` 产生粒子。
3. 记录原始双方蓄能截图作为人工对照，不加入 Git，除非项目现有流程明确要求保存验收图。

最小实现：

1. 在 `Game` 中增加一个普通回合蓄能粒子累计时间字段，初始为零。
2. 让 `emitTurnChargeParticles()` 接收当前渲染 `dt`。
3. 使用步骤 1 的纯函数推进累计时间；只有返回触发时才生成一批粒子。
4. 玩家视觉为 `charge` 时，在玩家位置调用 `emitTurnChargeAbsorb()`。
5. 敌方视觉为 `charge` 时，在敌方位置调用 `emitTurnChargeAbsorb()`。
6. 当状态不是 `resolving` 时把累计时间重置为零。
7. 不改变 `activeTurnResolution`、回合计时器、战斗输入日志或模拟 tick。

验证：

```powershell
npx vitest run tests/unit/turn-charge-cadence.test.ts tests/unit/game-simulation-boundaries.test.ts
npx playwright test tests/e2e/deterministic-battle.spec.ts
npx tsc --noEmit
git diff --check
```

预期：普通蓄能只使用新入口，确定性记录与不同渲染帧率下的战斗结果保持一致。

推荐提交：`fix(arena): reduce turn charge particle density`

## 6. 风险与限制

- 随机粒子不适合像素级快照测试，最终密度和遮挡程度必须结合截图人工验收。
- 正式构建只更新本地统一站点；临时公网隧道是否立即展示新资源取决于当前服务进程和浏览器缓存，部署验证应与代码验证分开记录。
- 如果第一版视觉仍偏亮，优先微调专用方法的尺寸或单批数量，不调整共享材质和全局 Bloom。
