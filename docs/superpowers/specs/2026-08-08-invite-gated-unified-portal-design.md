# 邀请制统一门户设计

日期：2026-08-08
状态：已批准，待书面复核
对应总规格：`docs/superpowers/specs/2026-08-01-nss-arena-complete-expansion-design.md`
对应总计划：`docs/superpowers/plans/2026-08-01-nss-arena-complete-expansion-implementation.md` 任务 4.4

## 1. 目标

把已经完成的邀请码兑换和本地设备身份接入统一门户，同时保持 Arena、NSS 定制器和现有战斗模式不变。

成功标准：

- 未认证玩家在门户只看到邀请入口。
- `?invite=<code>` 自动提供邀请码，玩家只填写昵称。
- 认证玩家刷新后通过 `/api/me` 恢复身份。
- 无效设备身份被清除并返回邀请入口；暂时断网不会删除有效本地身份。
- 门户显示昵称、本地金币、当前配装和六个模式入口。
- 只有定制器和竞技场可进入；其余入口显示明确阶段条件且不可导航。
- 门户和 Arena 分别构建，门户不初始化 Three.js 游戏。
- 桌面与 390×844 移动视口均无横向溢出，主要触摸目标不小于 44px。

## 2. 边界

本任务不实现进度同步、异步挑战、战役、生存、纹章编辑、朋友展厅或 WebSocket 身份认证。不修改战斗、属性、物理、AI、零件或奖励规则。

访问门禁属于门户客户端入口门禁，不声称构成服务端静态文件授权。业务 API 继续使用任务 4.3 的服务端身份认证；WebSocket 身份认证留到阶段 10。

## 3. 构建与启动架构

采用双 Vite 构建：

1. 门户构建输出到 `dist/site/`。
2. Arena 构建输出到 `dist/site/arena/`。
3. 定制器继续输出到 `dist/site/customizer/`。
4. 公共资源和 NSS 模型继续由统一构建脚本复制一次。

`VITE_APP_MODE=portal|arena` 决定 `src/main.ts` 启动哪个应用。`main.ts` 使用动态导入：门户分支只加载门户模块，Arena 分支才加载 `Game`。开发环境未提供该变量时，`/arena/` 使用 Arena，其余路径使用门户，从而让同一个 Vite 开发服务器支持两种入口。

统一构建脚本不再把静态 `site/index.html` 复制为生产首页；生产首页由门户 Vite 构建生成。既有 `./customizer/` 和 `./arena/` 相对路径保持不变。

生产静态服务只额外把 `/join` 和 `/join/` 映射到门户首页，以支持已批准的邀请链接格式；不增加任意路径的通用 SPA 回退。开发环境由 Vite 自身回退到门户入口。

## 4. 组件职责

### 4.1 `src/ui/inviteGate.ts`

只负责邀请表单 DOM、提交状态和错误显示：

- URL 已有邀请码时隐藏邀请码输入，仅显示昵称输入和邀请状态。
- URL 没有邀请码时显示邀请码与昵称输入。
- 提交期间禁用表单，防止重复兑换。
- 错误使用 `role="alert"`，状态使用 `role="status"`。
- 不直接访问数据库、解析服务器错误结构或启动 Arena。

### 4.2 `src/ui/portal.ts`

负责门户状态编排：

- `checking`：读取本地身份并验证。
- `guest`：渲染邀请入口。
- `offline`：保留本地身份，显示重试。
- `authenticated`：渲染玩家摘要和模式入口。

它调用现有 `localIdentity.ts`、`inviteClient.ts` 和 `loadProgression()`，不复制认证、存档迁移或配装计算规则。

### 4.3 `src/main.ts`

只选择门户或 Arena 启动函数，不包含门户 DOM、身份判断或战斗规则。

## 5. 身份数据流

首次进入：

```text
/join?invite=CODE 或 /?invite=CODE
  → 读取邀请码
  → 玩家填写昵称
  → 用非敏感探针确认 localStorage 可写
  → POST /api/invites/redeem
  → 验证返回身份
  → 写入 localStorage
  → 清除 URL 中 invite 参数
  → 渲染认证门户
```

刷新恢复：

```text
读取 localStorage
  → 无身份：邀请入口
  → 有身份：GET /api/me
      → 200：使用服务端昵称渲染门户
      → 401/403：清除身份并显示邀请入口
      → 网络错误/5xx：保留身份并显示重试状态
```

设备令牌不得写入 DOM、URL、控制台、错误文本或诊断输出。

## 6. 门户信息层级

视觉意图是私人竞技据点，而不是通用管理后台。沿用深色金属、青蓝能量线和少量暖金强调，不新增图片资产。

桌面布局：

- 顶部：产品名称、私人服务器标识、玩家昵称。
- 左侧摘要：金币、当前配装和身份状态。
- 右侧主区：2×3 模式入口。

移动布局：

- 单列滚动。
- 玩家摘要位于模式入口之前。
- 使用安全区内边距，按钮和链接至少 44px 高。
- 锁定说明允许换行，不通过缩小字号硬塞。

六个模式入口固定为：

| 入口 | 当前状态 | 行为或条件 |
|---|---|---|
| NSS 定制器 | 开放 | 导航到 `./customizer/` |
| RIPTOP Arena | 开放 | 导航到 `./arena/` |
| 好友挑战 | 锁定 | 阶段 5 解锁 |
| 八人战役 | 锁定 | 阶段 6 解锁 |
| 生存模式 | 锁定 | 阶段 7 解锁 |
| 纹章工坊 | 锁定 | 阶段 8 解锁 |

锁定入口使用不可交互元素或禁用按钮，不设置伪造链接，不导航到空页面。

金币与当前配装在任务 4.5 前读取现有本地存档：优先显示最新 NSS 组合 ID；没有 NSS 配装时显示现有三层配装摘要。门户只展示结果，不修改存档。

## 7. 错误处理

- 邀请无效、停用、耗尽和昵称错误显示服务端提供的安全文本。
- 兑换网络失败保留表单内容，允许重试。
- localStorage 探针失败时不发送兑换请求，避免白白消耗邀请码次数。
- 兑换后最终身份写入仍失败时，在当前页面内暂存返回身份并提供“重试保存”，不重复调用兑换 API；持久化成功前不进入认证门户。
- `/api/me` 返回身份错误时清除本地身份。
- `/api/me` 网络错误或 5xx 时不清除身份，显示连接重试。
- 未捕获错误不显示设备令牌或原始响应体。

## 8. 样式和可访问性

- 门户样式使用 `portal-`、邀请入口使用 `invite-gate-` 前缀，避免影响现有 Arena UI。
- 门户允许纵向滚动；Arena 继续保持全屏、无页面滚动。
- 表单包含可见标签、自动完成提示和明确焦点样式。
- 加载状态设置 `aria-busy`；错误与状态区域不会抢占输入焦点。
- 支持 `prefers-reduced-motion`，门户装饰动画可以关闭。
- 不使用闪烁、持续强烈震动或低对比度装饰文字。

## 9. 测试与验收

单元测试覆盖：

- 门户模式定义只有六项，开放与锁定状态正确。
- 当前配装摘要不会修改存档。
- 身份错误与暂时网络错误产生不同状态迁移。

Playwright 覆盖：

1. `?invite=` 首次进入时只需填写昵称，兑换后显示门户并保存身份。
2. 刷新时调用 `/api/me`，不重复兑换。
3. 伪造或过期令牌返回 401 后清理本地身份并显示邀请入口。
4. 暂时网络失败保留身份并提供重试。
5. 锁定入口不可导航，开放入口保留相对 URL。
6. 1280×800 和 390×844 无横向溢出，主要控件可见且触摸尺寸合格。
7. `/arena/` 仍可启动非空 Three.js Canvas，页面无未捕获异常。

服务端真实兑换、哈希和认证继续由 `scripts/test-auth.mjs` 验证；浏览器测试可拦截 API 响应以稳定覆盖门户状态，不替代服务端测试。

## 10. 明确限制

- 清除浏览器数据后无法恢复原设备身份。
- `localStorage` 身份要求最终公网部署使用 HTTPS，并保持前端无不可信脚本。
- 本任务不阻止知道静态路径的访客直接下载公开前端资源；真正的数据访问由认证 API 保护。
- 任务 4.5 完成前，金币和配装摘要仍是本机数据。
