# 指定好友真人房间设计

## 1. 目标

在保留现有随机真人匹配和确定性战斗规则的前提下，完成以下三项优化：

1. 公网 HTTPS 页面自动连接同源 `wss://`，不再错误添加 `:8080`。
2. 真人联机优先显示已认领身份的昵称；无身份玩家可以填写并本地保存游客昵称。
3. 玩家可以创建一个临时的一对一真人房间链接，指定朋友通过链接确认后加入同一场实时战斗。

本功能不修改装配属性、物理、伤害、博弈回合或结算规则。

## 2. 范围

### 2.1 包含

- 保留现有全服随机匹配入口。
- 新增“创建好友房间”入口和等待状态。
- 新增 `?room=<token>` 真人房间链接解析与加入确认。
- 新增游客昵称的本地保存。
- 新增纯 WebSocket 临时房间协议。
- 新增协议、服务端生命周期、客户端工具和双浏览器流程测试。

### 2.2 不包含

- 房间密码、观战、多人房间或房间列表。
- 离线房间、固定房间或服务器重启恢复。
- 游客账户注册、游客进度同步或游客身份升级。
- 指定房间战绩持久化。
- 对现有异步幽灵挑战的修改。

## 3. 产品规则

### 3.1 房间生命周期

- 创建者必须保持 WebSocket 在线并处于等待状态。
- 服务器创建不可预测的 URL 安全随机令牌，并只保存在内存中。
- 创建者取消、断开连接、进入其他匹配或服务器重启时，令牌立即失效。
- 第一位使用有效令牌加入的玩家成为唯一对手。
- 成功配对时令牌立即从等待表删除，不能再次使用。
- 定向房间错误不会让玩家自动进入随机队列。

### 3.2 身份与昵称

- 创建和加入真人房间不要求邀请码身份，游客可直接使用。
- 若浏览器存在合法 `LocalIdentity`，使用其 `displayName`，界面不允许在真人联机窗口覆盖该正式昵称。
- 若不存在正式身份，读取真人联机专用游客昵称；没有保存值时要求填写。
- 游客昵称提交成功后保存在当前浏览器，长度限制为去除首尾空格后的 1–32 个字符。
- 游客昵称不保证唯一，不携带玩家 ID、设备令牌、进度或授权能力。

### 3.3 加入体验

- 创建者在真人联机窗口选择“创建好友房间”。
- 创建成功后显示完整链接、复制按钮、等待状态和取消按钮。
- 朋友打开 `/arena/?room=<token>` 后，Arena 自动打开加入确认窗口。
- 窗口显示“加入指定好友房间”，并展示正式昵称或游客昵称输入框。
- 玩家点击“加入对战”后才建立 WebSocket 并提交加入请求。
- 无效、已使用或已失效链接停留在窗口并显示明确错误，不回退到随机匹配。
- 成功配对后复用现有场景准备、三秒倒计时、回合选择和战斗同步流程。

## 4. WebSocket 地址推导

`VITE_WS_URL` 继续具有最高优先级。未配置时：

- `https://example.com/arena/` 推导为 `wss://example.com/`，使用 HTTPS 默认端口。
- `https://example.com:8443/arena/` 推导为 `wss://example.com:8443/`，保持显式反向代理端口。
- HTTP 页面若本身运行在 `8080`，推导为同主机 `ws://<host>:8080/`。
- HTTP 开发或局域网页面运行在其他端口时，推导为同主机 `ws://<host>:8080/`。
- 推导结果清除路径、查询参数和哈希。

这使 Cloudflare Tunnel 等 HTTPS 反向代理走公开的 443 端口，同时保留本地 Vite/LAN 的独立 8080 匹配服务。

## 5. 协议设计

协议版本保持 v2，新增消息类型而不改变现有战斗消息结构。

### 5.1 客户端到服务器

| 类型 | 字段 | 用途 |
| --- | --- | --- |
| `JOIN_QUEUE` | `displayName`, `loadout` | 现有随机匹配，保持不变 |
| `CREATE_PRIVATE_ROOM` | `displayName`, `loadout` | 创建临时指定房间 |
| `JOIN_PRIVATE_ROOM` | `roomToken`, `displayName`, `loadout` | 使用令牌加入指定房间 |
| `CANCEL_QUEUE` | 无 | 取消随机等待或指定房间等待 |

### 5.2 服务器到客户端

| 类型 | 字段 | 用途 |
| --- | --- | --- |
| `PRIVATE_ROOM_CREATED` | `roomToken` | 创建成功，客户端据此生成完整链接 |
| `QUEUED` | `peerId` | 现有随机等待状态 |
| `MATCHED` | 现有字段 | 随机或指定配对成功，保持不变 |
| `ERROR` | `code`, `message` | 返回协议或房间失败 |

### 5.3 错误代码

- `INVALID_ROOM_TOKEN`：令牌类型、长度或字符格式不合法。
- `PRIVATE_ROOM_NOT_FOUND`：令牌不存在、已使用或创建者已经离线。
- `ALREADY_WAITING`：连接已经位于随机队列或指定房间等待表。
- `ALREADY_MATCHED`：连接已经进入战斗房间。
- 现有 `INVALID_LOADOUT`、`CATALOG_MISMATCH` 和协议错误继续适用。

## 6. 服务端设计

- 在现有单一 `waitingPlayer` 之外增加 `privateRooms: Map<token, WebSocket>`。
- 客户端元数据记录当前等待类型及私人房间令牌，保证一个连接只能处于一种等待状态。
- `CREATE_PRIVATE_ROOM` 复用现有昵称和装配校验，通过后生成高熵 URL 安全令牌并加入映射。
- `JOIN_PRIVATE_ROOM` 严格校验令牌、昵称和装配；找到在线且不同于加入者的创建者后，先原子删除等待令牌，再调用现有 `createRoom(host, guest)`。
- `CANCEL_QUEUE` 和 `close` 都通过同一个等待清理函数删除随机或私人等待状态。
- `createRoom()`、准备超时、回合超时、心跳和战斗消息转发保持不变。
- 私人房间不写 SQLite，也不加入备份。

## 7. 客户端设计

### 7.1 网络客户端

- 增加创建和加入私人房间的方法。
- 接收 `PRIVATE_ROOM_CREATED` 后保存当前令牌并进入私人等待状态。
- 现有 `MATCHED` 处理保持统一，不为私人房间复制战斗分支。
- 取消或断开时清空本地令牌和房间会话状态。

### 7.2 昵称解析

- 新增小型昵称工具，职责仅限：读取正式身份、读取/保存游客昵称、校验并返回联机显示名。
- 正式身份优先级高于游客昵称。
- 使用独立 localStorage 键，避免修改 `LocalIdentity` 的结构和认证逻辑。

### 7.3 真人联机窗口

- 将过时的“局域网”文案更新为“真人联机”。
- 保留服务器地址输入用于诊断和手动覆盖。
- 提供“随机匹配”和“创建好友房间”两个入口。
- 私人等待状态显示只读链接和复制按钮。
- `?room=` 存在时切换为加入确认状态，不显示创建和随机匹配操作。
- 复制失败时保留可手动选择的链接文本并显示简短提示。

### 7.4 Game 接入

- Arena 启动时解析 `room` 参数并打开对应确认状态。
- 所有联机入口通过统一的当前装配构造函数生成 `OnlineLoadout`。
- 将当前写死的 `Player` 替换为昵称解析结果。
- 匹配成功后的 `prepareOnlineBattle()` 及战斗流程不变。

## 8. 安全与校验

- 令牌只允许固定长度的 URL 安全字符，服务器不接受任意长字符串。
- 令牌由 Node 加密随机源生成，不使用房间数量、时间戳或玩家名称。
- 链接持有者即可加入；这是本阶段唯一的房间授权模型。
- 客户端输入不可信，服务端继续校验昵称、装配、协议版本和消息大小。
- 昵称只作为纯文本渲染，不插入 HTML。
- 私人房间不会绕过后续房间成员检查；战斗消息仍必须携带匹配后的 `roomId`。

## 9. 验证设计

### 9.1 单元测试

- HTTPS 默认端口、HTTPS 显式端口、HTTP 8080、HTTP 开发端口的 WebSocket URL 推导。
- 正式身份昵称优先、游客昵称读取与保存、空白和超长昵称拒绝。
- `PRIVATE_ROOM_CREATED` 解析与无效消息拒绝。

### 9.2 服务端协议测试

- 创建私人房间并由正确令牌加入。
- 双方收到正确的对手昵称、装配、角色和相同 `roomId`。
- 令牌配对后不能再次使用。
- 创建者取消或断线后令牌失效。
- 无效令牌、创建者自连、重复等待和已匹配连接被拒绝。
- 私人等待者不会被随机队列玩家匹配。
- 现有随机匹配、准备、战斗消息、超时和混合装配测试继续通过。

### 9.3 浏览器流程测试

- 浏览器 A 使用正式身份创建房间并获得链接。
- 隔离的浏览器 B 无正式身份，填写游客昵称并通过链接加入。
- 双方界面显示各自昵称和对手昵称，进入同一场战斗。
- 失效链接显示明确错误且不会进入随机匹配。

### 9.4 完整回归

- TypeScript 检查。
- 单元测试。
- 服务端测试。
- 生产构建与统一站点验证。
- 双浏览器真实输入路径检查、控制台错误检查和 Arena Canvas 非空检查。

## 10. 成功标准

- 公网 HTTPS 页面默认连接 `wss://当前域名/`，无需手动删除 `:8080`。
- 正式玩家显示认领昵称，游客昵称首次保存后可复用。
- 创建者可以复制一个只在其在线等待期间有效的真人房间链接。
- 一位朋友可以确认昵称后通过链接加入，其他人不能重复使用同一链接。
- 指定房间与随机匹配互不串队。
- 配对后的战斗规则和现有确定性结果不变。
- 所有新增测试与既有回归通过。
