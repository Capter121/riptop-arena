# 私人服务器基础备份与恢复设计

日期：2026-08-09

状态：设计已批准，待用户复核书面规格

对应总计划：`docs/superpowers/plans/2026-08-01-nss-arena-complete-expansion-implementation.md` 任务 4.6

## 1. 目标

为部署到公网、仅供受邀朋友使用的 NSS Arena 服务器提供最小而可靠的基础备份与恢复能力。服务器运行期间可以生成一致的 SQLite 快照；恢复必须停服，并且只能写入不存在的目标，不能覆盖、合并或自动删除现有数据。

完成标准：

- WAL 模式数据库在服务器运行期间能够生成一致快照。
- 备份包含数据库、实际存在的上传文件以及可校验清单。
- 每份备份位于独立时间戳目录，不覆盖旧备份。
- 恢复前验证清单、SHA-256、SQLite 完整性、迁移版本和目标路径。
- 恢复只允许写入不存在的数据库和上传目标。
- dry-run 能验证计划而不创建或修改文件。
- 不新增第三方依赖，不改变身份、进度、战斗或门户行为。

## 2. 已确认的当前状态

- 数据库默认位于 `data/arena.sqlite`，可由 `DATABASE_PATH` 覆盖。
- `openDatabase()` 启用外键、busy timeout 和 WAL。
- 当前运行时为 Node.js v24，并原生提供 `node:sqlite.backup()`。
- 当前迁移版本为 001、002 和 003。
- 纹章上传尚未实现，因此现在可能不存在上传目录。
- 总计划要求备份 SQLite 和上传目录、提供 dry-run、记录版本与校验值，并使用临时目录验证恢复。

## 3. 范围

### 3.1 本任务包含

- SQLite 在线一致性快照。
- 实际存在的上传目录逐文件复制。
- 版本化 `manifest.json`。
- 文件大小和 SHA-256 校验。
- SQLite `PRAGMA quick_check`。
- 已应用迁移版本记录与恢复兼容性检查。
- 停服、非覆盖式恢复。
- 备份和恢复 dry-run。
- CLI 命令、自动测试和 Git 忽略规则。

### 3.2 明确不做

- 自动定时备份。
- 云存储或远程上传。
- ZIP、压缩包或加密归档。
- 自动删除或轮换旧备份。
- 在线恢复。
- 覆盖式恢复、`--force` 或自动清空目标。
- 上传服务、纹章业务或图库数据模型。
- 身份、进度、战斗、属性、奖励和门户行为修改。

## 4. 配置与命令

### 4.1 路径来源

- 源或恢复目标数据库：`DATABASE_PATH`；未设置时沿用 `data/arena.sqlite`。
- 备份根目录：`BACKUP_ROOT`；执行备份时 `--output <目录>` 优先于环境变量。
- 上传目录：`UPLOAD_ROOT`；未设置或目录不存在时，清单记录未包含上传数据。

备份时 `--output` 与 `BACKUP_ROOT` 至少提供一项；两者都缺失时直接报错，不猜测或创建项目内默认备份位置。恢复始终通过 `--backup` 显式选择具体备份目录。

生产部署应将 `BACKUP_ROOT` 指向独立持久卷或外部磁盘。备份与生产数据库位于同一磁盘时，无法防范整盘故障。

### 4.2 CLI

```powershell
node scripts/backup-private-server.mjs
node scripts/backup-private-server.mjs --output E:\nss-backups
node scripts/backup-private-server.mjs --dry-run

node scripts/restore-private-server.mjs --backup E:\nss-backups\nss-private-20260809T010203Z
node scripts/restore-private-server.mjs --backup E:\nss-backups\nss-private-20260809T010203Z --dry-run
```

同时在 `package.json` 提供：

- `npm run backup:server`
- `npm run restore:server -- --backup <目录>`
- `npm run test:backup`

`test:backup` 接入现有 `test:server` 链。

### 4.3 dry-run

备份 dry-run：

- 解析并规范化来源和目标绝对路径。
- 检查源数据库、上传目录类型和目标冲突。
- 输出计划动作。
- 不打开数据库，不创建目录，不复制文件。

恢复 dry-run：

- 完整读取并验证清单、哈希、数据库完整性和迁移兼容性。
- 检查恢复目标是否不存在。
- 不创建或修改任何目标文件。

## 5. 备份目录与清单

每次备份创建一个新的 UTC 时间戳目录：

```text
<BACKUP_ROOT>/
└── nss-private-20260809T010203Z/
    ├── manifest.json
    ├── arena.sqlite
    └── uploads/          # 仅源目录实际存在时生成
```

目标目录已存在时立即失败，不覆盖、不合并。脚本不自动删除旧备份。

清单固定使用 `formatVersion: 1`：

```json
{
  "formatVersion": 1,
  "createdAt": "2026-08-09T01:02:03.000Z",
  "database": {
    "path": "arena.sqlite",
    "bytes": 123456,
    "sha256": "...",
    "migrationVersions": [1, 2, 3],
    "quickCheck": "ok"
  },
  "uploads": {
    "included": false,
    "files": []
  }
}
```

上传文件条目只记录相对于备份目录的规范路径、字节数和 SHA-256。清单不记录生产服务器绝对路径、设备令牌、邀请码或数据库内容。

## 6. 模块边界

新增最小文件：

- `server/storage/private-server-archive.mjs`
  - 路径校验、在线快照、文件复制、清单生成与验证、安全恢复。
- `scripts/backup-private-server.mjs`
  - 解析备份参数和环境变量，调用共享模块并输出结果。
- `scripts/restore-private-server.mjs`
  - 解析恢复参数和环境变量，调用共享模块并输出结果。
- `scripts/test-private-server-archive.mjs`
  - 使用独立临时目录覆盖备份与恢复行为。

共享模块只服务本任务，不建立通用归档框架。CLI 不包含数据库或文件业务逻辑。

## 7. 在线备份数据流

1. 解析并规范化数据库、上传目录和备份根目录的绝对路径。
2. 验证源数据库存在且为普通文件，禁止因为路径错误创建空数据库。
3. 验证目标备份目录不位于上传目录内部，避免递归复制。
4. 创建新的时间戳目录；该目录必须不存在。
5. 使用 `node:sqlite.backup()`生成 `arena.sqlite` 一致性快照。
6. 对快照执行 `PRAGMA quick_check` 并读取 `schema_migrations`。
7. 如果上传目录存在，逐文件复制；不跟随符号链接，不接受非普通文件。
8. 计算数据库和全部上传文件的字节数及 SHA-256。
9. 最后写入 `manifest.json`。

清单最后写入意味着中断目录天然无效。失败时保留现场并报告路径，不自动删除部分目录。

## 8. 恢复数据流与保护规则

1. 强制要求显式传入 `--backup <目录>`。
2. 备份目录和清单必须为普通目录与普通文件，且不能通过符号链接绕过路径边界。
3. 严格校验清单键、字段类型、`formatVersion`、重复条目和规范相对路径。
4. 拒绝绝对路径、`..`、未知文件、未记录文件和符号链接。
5. 重新计算每个文件的大小与 SHA-256。
6. 对备份数据库执行 `PRAGMA quick_check`。
7. 将清单迁移版本与当前迁移文件比较：
   - 旧版本允许恢复，服务启动时由现有迁移器升级。
   - 备份包含当前程序无法识别的新版本时拒绝恢复。
8. 目标数据库和目标上传目录都必须不存在。
9. 先复制上传文件，最后放置数据库，避免服务在资源未完成时看到数据库。
10. 对恢复后的文件再次校验哈希，并再次执行数据库完整性检查。

恢复脚本不提供 `--force`，不覆盖、不合并、不删除。生产恢复操作顺序为：停止服务器，手动把旧数据移动到明确保留目录，执行 dry-run，执行恢复，启动服务，检查 `/health`。

脚本不能防止管理员在恢复过程中手动启动服务；操作纪律要求恢复完成前保持停服。目标数据库必须不存在，使正常运行中的现有实例无法被原地覆盖。

## 9. 路径与文件安全

- 所有输入先解析为绝对路径，再检查包含关系。
- 恢复只接受清单声明的规范相对路径。
- 不跟随符号链接、目录联接或其他非普通文件。
- 备份目标不能嵌套在上传来源内。
- 目标目录已存在时拒绝执行。
- 备份目录尽可能使用仅当前用户可读写权限；Windows 服从现有 ACL。
- 不使用递归删除，也不自动清理失败现场。

## 10. 输出与错误处理

- 成功时向 stdout 输出单个 JSON 摘要，包括操作、状态、备份路径、文件数和总字节数。
- dry-run 摘要明确包含 `dryRun: true`。
- 失败时向 stderr 输出简洁原因并返回非零退出码。
- 普通错误不输出数据库内容、设备令牌、邀请码或原始敏感对象。
- SQLite 不完整、哈希不一致、清单不兼容、目标冲突和路径越界分别给出可定位的安全文本。
- 失败后不自动撤销或删除已经写入的部分文件；输出明确指出需要人工检查的路径。

## 11. 上传目录一致性

本任务只备份实际存在的上传目录，不创建上传业务。未来上传功能必须采用“写入临时文件，完成后原子改名”的方式发布文件，确保在线备份只会看到完整文件。阶段 8 实现上传服务时需复核这一契约。

## 12. 测试设计

测试全部使用独立临时目录和临时数据库，不读取或修改真实 `data/`、`BACKUP_ROOT` 或 `UPLOAD_ROOT`。

覆盖：

1. 数据库保持打开且处于 WAL 模式时成功备份。
2. 快照包含身份、进度和迁移记录。
3. 每次执行使用新目录，不覆盖已有目录。
4. 备份 dry-run 不创建文件。
5. 上传目录不存在时清单记录 `included: false`。
6. 嵌套上传文件复制并通过大小与哈希校验。
7. 符号链接或非普通文件被拒绝；平台不允许创建符号链接时至少验证分类和路径拒绝逻辑。
8. 损坏哈希、错误清单版本、路径穿越、重复条目、未知文件和未记录文件被拒绝。
9. 损坏 SQLite 快照被拒绝。
10. 包含未知新迁移版本的备份被拒绝。
11. 旧迁移版本恢复后能够由当前迁移器升级。
12. 目标数据库或上传目录存在时拒绝恢复且保持原文件不变。
13. 完整备份恢复到空目标后，文件哈希与数据库内容一致。
14. 恢复 dry-run 不创建或修改目标。
15. CLI 成功输出 JSON，失败返回非零状态且不泄漏敏感值。

## 13. 风险与限制

- 备份未加密，持有数据库快照的人可以读取玩家数据；备份根目录必须按敏感数据保护。
- 本地或同盘备份无法防范整盘损坏，公网部署应使用独立持久卷。
- 不自动清理意味着管理员必须监控剩余空间。
- 中断操作保留部分目录，管理员需要手动检查或移动这些目录。
- 在线上传一致性依赖未来上传服务的原子发布方式。
- 恢复期间的停服由操作流程保证，脚本不实现跨进程全局锁。
