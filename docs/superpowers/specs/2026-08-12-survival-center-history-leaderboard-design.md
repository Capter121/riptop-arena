# 生存中心运行记录、个人最佳与排行榜设计

日期：2026-08-12
状态：待用户规格批准

## 1. 目标

将 `/survival/` 完善为邀请制朋友服务器的生存模式中心，集中展示当前活动运行、个人最佳、当前排名、朋友排行榜和个人历史运行记录。

本阶段不改变生存战斗、波次生成、计分、奖励或最佳成绩比较规则。

## 2. 范围

### 2.1 包含

- 当前活动运行或开始新运行的入口。
- 个人最佳成绩及当前服务器排名。
- 前 20 名朋友排行榜，并通过不透明游标继续加载。
- 当前身份最近 20 条正常战败运行记录，并通过独立游标继续加载。
- 桌面与手机端响应式布局。
- 加载、空数据、离线、失败和重试状态。

### 2.2 不包含

- 每日、每周、赛季或公开排行榜。
- 逐波战斗日志、录像、观战或运行分享。
- 排行榜筛选、搜索、玩家主页或好友关系系统。
- 主动放弃记录展示。
- 历史记录删除、重命名或编辑。
- 新数据库表或迁移。

## 3. 权威数据与排序

- `survival_runs` 是个人运行历史的权威来源。
- `survival_best_scores` 是个人最佳与排行榜的权威来源。
- 客户端只解析和展示服务端数据，不重新计算排名、最佳成绩或历史结果。
- 排行榜沿用既有确定性顺序：总分降序、最高完成波次降序、BOSS 数降序、最终完整度降序、达成时间升序、玩家 ID 升序。
- 历史记录按完成时间降序；相同完成时间按运行 ID 降序，保证分页稳定。
- 只有 `status = completed` 且最终摘要 `abandoned = false` 的运行进入历史记录。
- 主动放弃不会展示，也不会更新个人最佳。

## 4. 服务端设计

### 4.1 新增接口

`GET /api/survival/history?limit=20&cursor=...`

响应：

```json
{
  "items": [
    {
      "runId": "uuid",
      "score": 4200,
      "highestCompletedWave": 4,
      "bossesDefeated": 1,
      "finalIntegrity": 0,
      "riskLevel": 2,
      "loadoutSummary": {},
      "achievedAt": "2026-08-12T10:00:00.000Z"
    }
  ],
  "nextCursor": null
}
```

约束：

- 使用现有 Bearer token 与 `X-Player-Id` 身份认证。
- 只读取当前认证玩家的数据，不接受玩家 ID 参数。
- `limit` 默认 20，范围为 1–50。
- cursor 是 Base64URL 编码的不透明数据，只表达上一页末项的 `achievedAt` 和 `runId`。
- cursor 格式无效、找不到对应锚点或锚点已不再符合查询条件时返回 `400 INVALID_SURVIVAL_HISTORY_CURSOR`。
- 返回字段执行严格契约校验，不包含逐波结果或完整服务端行。

### 4.2 现有接口

- `GET /api/survival` 继续返回活动运行、个人最佳、里程碑和排行榜首屏。
- `GET /api/survival/leaderboard?limit=20&cursor=...` 继续承担排行榜分页。
- 历史分页和排行榜分页相互独立，不共享 cursor。

### 4.3 查询约束

历史查询只选择：

- `player_id = 当前认证玩家`
- `status = 'completed'`
- 最终摘要存在
- `final_summary_json.abandoned = false`

从现有运行行读取冻结装配和最终摘要，不新增或回填数据结构。

## 5. 客户端数据模型

生存客户端新增：

- `SurvivalHistoryEntry`
- `SurvivalHistoryPage`
- `getHistory({ limit, cursor })`

解析要求：

- 响应必须精确包含 `items` 和 `nextCursor`。
- 每条记录必须拥有合法 UUID、非负整数统计、0–3 风险等级、合法 NSS V2 装配和 ISO 时间。
- 不接受额外字段、非法日期、非法装配或空字符串 cursor。

分页状态分别保存：

- 排行榜已加载条目与 `leaderboardCursor`
- 历史记录已加载条目与 `historyCursor`

追加页面时：

- 排行榜按 `playerId` 去重。
- 历史记录按 `runId` 去重。
- 请求失败保留已有数据和原 cursor，允许原请求重试。
- 页面身份发生变化后，旧请求结果不得写入新身份视图。

## 6. 生存中心界面

页面为单页静态游戏菜单，不启动第二个持续 3D 场景。

### 6.1 运行控制区

有活动运行时展示：

- 当前波次和类型。
- 累计得分、完整度、爆裂风险和风险等级。
- 冻结装配摘要。
- 主操作“继续挑战”。

无活动运行时展示：

- 当前同步的 NSS 装配摘要。
- 主操作“开始新运行”。
- 没有合法 NSS V2 装配时禁用开始操作，并提供“前往定制器”。

活动运行始终使用创建时冻结的装配，外部改装不改变该运行。

### 6.2 个人最佳

突出展示：

- 最高分。
- 最高完成波次。
- 当前排名。

补充展示：BOSS 数、最终完整度、风险等级、达成时间和冻结装配。没有个人最佳时展示明确空状态，不显示伪造的零分排名。

### 6.3 朋友排行榜

- 首屏使用 Hub 返回的前 20 名。
- 当前玩家条目高亮。
- 无论当前玩家是否在已加载条目内，都固定显示“我的排名”；没有有效成绩时显示“暂无排名”。
- 存在 `nextCursor` 时显示“加载更多”。
- 加载期间按钮禁用；失败后保留列表并允许重试。
- 排行榜不可用不阻止开始或继续运行。

### 6.4 我的运行记录

- 首次独立请求最近 20 条正常战败记录。
- 每条展示总分、完成波次、BOSS 数、最终完整度、风险等级、冻结装配和完成时间。
- 主动放弃记录完全不展示。
- 存在 `nextCursor` 时显示“加载更多”。
- 空数据、初次加载失败和追加失败各有独立状态。

## 7. 信息层级与响应式

- 桌面端首屏为运行控制与个人最佳双栏；排行榜与运行记录位于下方。
- 手机端严格单列，运行主操作优先，其后为个人最佳、排行榜和运行记录。
- 排行榜使用紧凑排名行；运行历史使用可换行摘要条目，避免嵌套卡片。
- 分数使用稳定宽度的数字容器，避免位数变化导致布局移动。
- 主要按钮最小高度 44 CSS px，并具备 hover、pressed、focus 和 disabled 状态。
- 使用移动安全区内边距；长昵称、长零件 ID 和高位数得分必须换行或稳定收缩。
- 桌面与 390×844 手机视口不得出现横向滚动、文字裁切或控制重叠。
- 本阶段不生成新图标或图片资源，沿用现有竞技场色彩、边框和状态色。

## 8. 错误处理

- Hub 失败：整页显示身份保留的重试状态。
- 排行榜失败：只替换排行榜区域，不影响运行控制和历史记录。
- 历史失败：只替换历史区域，不影响运行控制和排行榜。
- 分页失败：保留已加载内容与原 cursor，不前移页码。
- `401/403`：提示返回私人竞技据点重新确认身份。
- 严格响应解析失败：作为服务器数据异常处理，不展示部分不可信数据。

## 9. 测试与验收

### 9.1 服务端

- 认证缺失和跨身份隔离。
- 主动放弃过滤。
- 完成时间与运行 ID 的稳定倒序。
- 默认 20 条、1–50 limit 边界和继续分页。
- 非法、陈旧和跨身份 cursor。
- 个人最佳和排行榜既有排序规则不回归。

### 9.2 客户端

- Hub、排行榜和历史严格响应解析。
- 非法 UUID、日期、风险、装配、额外字段和 cursor 被拒绝。
- 活动运行、无运行、无个人最佳、无排名和空历史展示。
- 当前玩家不在前 20 时仍显示固定“我的排名”。
- 分页追加、去重、失败保留和重试。
- 身份切换不会应用旧请求结果。

### 9.3 浏览器与回归

- 桌面和 390×844 手机端检查长昵称、高分、20 行排行榜及 20 条历史。
- 无横向溢出，主要按钮至少 44px，内容在安全区内可到达。
- 开始/继续运行、两个“加载更多”和错误重试可操作。
- 页面与控制台无错误。
- TypeScript、完整 Vitest、生存契约/服务/HTTP、数据库测试、生产构建和 `git diff --check` 全部通过。

## 10. 成功标准

- 玩家能在生存中心继续活动运行或开始新运行。
- 玩家能看到权威个人最佳及当前排名。
- 玩家能浏览朋友榜并稳定继续加载。
- 玩家能浏览自己的正常战败历史，且看不到主动放弃记录。
- 任一非核心列表接口失败都不会阻止当前生存运行。
- 普通、战役、好友挑战和真人模式行为不变。
