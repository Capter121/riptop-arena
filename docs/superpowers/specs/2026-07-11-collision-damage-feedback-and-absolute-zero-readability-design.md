# Collision Damage Feedback and Absolute Zero Readability

## Goal

Restore readable DNF-style HP loss feedback for physical top collisions and reduce collision overexposure in the Absolute Zero Hologrid arena without removing its real-time mirror identity.

The change must preserve combat damage values, physics behavior, skill lightning, burst finish spectacle, and the existing user changes to top material metalness.

## Confirmed Causes

### Collision damage has no UI event

`BattlePhysicsSystem.resolveCollision()` still subtracts physical collision damage directly from each top's `integrity`, but it emits only generic `spark` and `impact` events. The actual damage values and damaged sides never reach the UI layer.

`FloatingTextManager` exists in the workspace, but the current `Game` does not attach or update it. Turn/collision damage therefore has no world-space damage-number presentation.

### Absolute Zero doubles bright collision effects through reflection

Ordinary collisions emit additive orange-white sparks. Strong sparks automatically trigger additive cyan lightning. The Absolute Zero floor uses a bright cyan-tinted real-time `Reflector`, while Bloom is driven by total energy without a theme-specific cap.

During a collision, sparks and lightning are visible directly and in the mirror, then Bloom expands both contributions. This produces a bright cyan-white patch that obscures the tops.

## Selected Approach

Keep the real-time mirror, but reduce its light contribution and apply theme-aware collision effects. Restore collision damage numbers through a typed event instead of reading HP differences from the UI.

This is preferred over disabling the mirror because the mirror is a defining part of the Absolute Zero arena. It is preferred over reducing global renderer exposure because global exposure would also darken the background and top materials.

## Collision Damage Feedback

### Typed event

Add a `collision_damage` event to the existing event map.

Payload:

```ts
{
  side: 'player' | 'enemy';
  amount: number;
  x: number;
  z: number;
  intensity: number;
}
```

Emit one event for each top that receives positive collision HP damage. Use the final applied HP delta after shields, suppression, scaling, and clamping. Do not emit when collision damage is suppressed during turn approach/resolution.

### Floating damage numbers

Attach one `FloatingTextManager` to the game mount and update it once per frame.

For physical collision damage:

- Display rounded integer values such as `-18`.
- Player damage uses warm red; enemy damage uses pale orange/yellow.
- Heavy collision values receive a modest size increase, not the full critical-hit treatment.
- Anchor text above the damaged top's world position.
- Skip projection when the top is behind or outside the camera.

### Burst control and aggregation

Physics can produce contacts at an 80 ms cooldown, so raw one-element-per-event rendering can become noisy.

Aggregate damage for the same side within a 120 ms window:

- update the active number instead of spawning another element,
- add the new amount to the displayed total,
- refresh its rise/fade lifetime,
- preserve the highest collision intensity in the window.

Player and enemy aggregation are independent. Turn damage, `BLOCK`, `MISS`, and critical text remain separate events and are not merged with physical collision damage.

## Absolute Zero Readability

### Mirror tint

Change the desktop reflector tint from bright cyan to a darker ice-blue/navy value. The mirror remains visible, but reflected sparks no longer start from an already bright base.

The mobile metallic fallback should use the same darker color family. No change is required to the existing 1024-pixel reflector resolution cap.

### Ice material response

Reduce transmission on the Absolute Zero bowl/base materials and increase roughness slightly. This preserves the glass-ice identity while preventing bright effects from reading as a white luminous surface.

Do not change top material metalness in this feature. Existing uncommitted changes in `src/scene/topMaterials.ts` are outside this implementation's ownership.

### Theme-aware Bloom

When `arenaManager.getTheme()` is `absolute_zero`, cap or multiply the dynamic Bloom strength so it remains below the normal arena maximum.

Use this initial formula:

```text
normalBloom = 0.65 + energyContribution
absoluteZeroBloom = min(normalBloom * 0.62, 1.05)
```

Other arenas retain their current Bloom behavior.

### Theme-aware ordinary collision effects

For generic `spark` events in Absolute Zero:

- multiply particle intensity by 0.55,
- raise the threshold for automatic decorative cyan lightning above the maximum ordinary collision intensity, effectively disabling it for normal physical contacts,
- retain lightning generated by skills, shield blocks, counters, and burst finishes.

This distinction is based on event source: only the generic `spark` listener is toned down. Explicit calls to `LightningFX.strike()` for gameplay-significant effects remain intact.

## Architecture and Files

- `src/utils/events.ts`: add the typed `collision_damage` event.
- `src/gameplay/battlePhysics.ts`: calculate final applied collision deltas and emit the event.
- `src/app/game.ts`: attach/update floating text, consume collision damage events, and apply theme-aware generic sparks and Bloom.
- `src/ui/floatingTextManager.ts`: add per-side collision aggregation and intensity-scaled styling.
- `src/scene/arenaVisuals.ts`: darken reflector/fallback tint.
- `src/scene/arena.ts`: adjust only Absolute Zero ice bowl/base transmission and roughness.

The implementation must not edit `src/scene/topMaterials.ts`.

## Edge Cases

- A shielded top receives no damage number.
- Suppressed collision damage receives no damage number.
- If HP is clamped at zero, display only the HP actually removed.
- Every positive damage delta is accumulated; rendered totals are rounded to at least 1 while positive.
- Repeated contacts refresh an existing number without leaking DOM elements.
- Leaving battle or starting a new battle clears pending collision aggregation.
- Off-camera text is hidden rather than projected to an invalid position.
- Absolute Zero tuning affects ordinary collision decoration only; skill readability and finish effects remain unchanged.

## Verification

### Automated checks

- Run `npm run build`.
- Run `git diff --check`.

### Browser scenarios

1. Force a normal physical collision in Classic Grid and verify both damaged tops display the correct rounded HP deltas.
2. Trigger rapid repeated contacts and verify each side shows one accumulating number rather than a stack of elements.
3. Verify shielded and damage-suppressed collisions do not show false damage.
4. Verify HP bar values and displayed collision totals agree with the actual `integrity` change.
5. Run the same collision in Absolute Zero and capture a screenshot during peak effect brightness.
6. Confirm both tops remain visually distinguishable during the Absolute Zero collision.
7. Verify generic collision lightning is absent in Absolute Zero while skill lightning and burst lightning still render.
8. Verify Classic Grid and Neon Magma collision effects retain their existing strength.
9. Verify desktop mirror and mobile fallback remain functional with no console/page errors.

## Success Criteria

- Every positive physical collision HP delta produces readable, correctly targeted damage feedback.
- Repeated contacts create at most one active aggregated collision number per side.
- Displayed accumulated damage differs from actual HP loss by no more than rounding error.
- At the peak of an ordinary Absolute Zero collision, the silhouettes and primary colors of both tops remain distinguishable.
- Absolute Zero retains a visible mirror/reflection effect.
- Skill and burst lightning remain unchanged.
- Build, battle flow, and other arena themes remain functional.
