# NSS 定制器完整装配分享协议 V2 设计

日期：2026-08-02
状态：已批准，待实施计划

## 1. 背景

当前定制器分享链接只包含 `combo=nss-p2c-xxxx`，可以恢复五件零件，但不能恢复用户选择的五层附加属性。二维码和 PNG 装备卡沿用同一旧链接，因此朋友打开后只能得到核心对应的默认属性，无法重现原装配的属性共鸣和流派解释。

本阶段是总体路线任务 2.5。它建立严格版本化的分享协议 V2，同时继续读取旧链接。该协议只传递基础输入，不传递可重新计算或可伪造的派生结果。

## 2. 目标

1. 新分享链接完整保存五件零件和五层附加属性。
2. 链接携带分享 schema、零件目录和属性规则版本。
3. 旧链接继续可用，并明确提示其属性已按默认值迁移。
4. 文本框、剪贴板、二维码和 PNG 卡片始终使用同一规范化 URL。
5. 为未来纹章作品保留严格格式的可选 ID，同时不实现虚假纹章加载。
6. 保持战斗、流派、规则预设、本地存档 schema 和 Arena 链接不变。

## 3. 成功标准

- 任意合法零件组合和合法五层属性都能生成唯一规范化 V2 URL，并无损恢复。
- 新链接只包含基础输入与版本，不包含共鸣、流派、概念属性或规则预设。
- 旧 `?combo=...` 链接使用核心默认属性恢复，并显示一次非阻断迁移提示。
- 非法或未知未来版本不部分载入，统一恢复 Storm Attack 与默认属性。
- 合法纹章 ID 可在同一分享会话中继续转发，但不进入历史、存档或战斗。
- 分享文本、复制内容、页面二维码和 PNG 二维码内容完全一致。
- desktop/mobile 分享 E2E、PNG 解码回归和现有 288 组合契约全部通过。

## 4. 范围

### 4.1 纳入范围

- 分享 URL schema V2。
- 五层属性编码与解析。
- 分享、目录和属性规则版本。
- 旧 URL V1 迁移。
- 可选纹章 ID 的格式校验和会话级转发。
- 分享文本、复制、二维码和 PNG 卡片回归。

### 4.2 不纳入范围

- 修改本地存档 V1/V2。
- 修改 Arena `loadoutVersion=1` 链接。
- 让 Arena 消费五层属性；该工作属于后续战斗接入阶段。
- 分享规则预设或当前违规状态。
- 保存构筑流派、共鸣、概念属性或最终战斗倍率。
- 加载、显示、查询或鉴权纹章作品。
- 短链接服务、签名、防篡改或服务端存储。

## 5. V2 URL 格式

### 5.1 参数

规范化参数顺序固定为：

1. `sv=2`：分享 schema 版本。
2. `cv=1`：零件目录版本。
3. `rv=1`：属性规则版本。
4. `combo=nss-p2c-xxxx`：现有稳定组合 ID。
5. `a=CORE,BLADE,ASSIST,GEAR,TIP`：五层属性，顺序固定为核心、主刀、辅助环、齿轮、轴尖。
6. `emblem=emblem_...`：可选纹章 ID。

示例：

```text
?sv=2&cv=1&rv=1&combo=nss-p2c-0138&a=LIGHT%2CFIRE%2CFIRE%2CWATER%2CEARTH
```

`URLSearchParams` 负责百分号编码，因此逗号在最终浏览器 URL 中可显示为 `%2C`。解析器按解码后的逗号分隔值校验。

### 5.2 版本来源

修改 `battle-top-designer/shared/nss/versions.json`，增加：

```json
"shareSchemaVersion": 2
```

`cv` 使用同文件的 `catalogVersion`，`rv` 使用 `affinityRulesVersion`。生成器和解析器共同读取该文件，不在多个模块重复版本常量。

### 5.3 五层属性

`a` 必须在解码后满足：

- 恰好五项。
- 顺序固定为 `core, blade, assist, gear, tip`。
- 每项必须是现有大写属性之一：`WIND`、`FIRE`、`WATER`、`WOOD`、`EARTH`、`LIGHT`、`DARK`。
- 不接受空项、前后空格、小写、混合大小写或第六项。

### 5.4 纹章 ID

可选 `emblem` 必须匹配：

```text
^emblem_[a-z0-9_-]{1,48}$
```

本阶段只验证和转发字符串，不加载网络资源，不把 ID 当作权限证明。

## 6. 严格参数规则

### 6.1 V2

V2 必须各有且仅有一个 `sv`、`cv`、`rv`、`combo` 和 `a`。`emblem` 与 `test` 可选，但出现时也只能有一个。`test` 只允许值 `1`。

以下情况全部视为无效：

- 必需参数缺失或重复。
- 版本不是当前精确值。
- 未知、大小写错误或槽位不匹配的组合。
- 非法五层属性。
- 非法纹章 ID。
- 未允许参数。
- 任意参数重复。
- 新旧形式混搭，例如只有 `combo + emblem`，或有 `sv` 但缺少其他 V2 参数。

参数在输入 URL 中的顺序不影响解析；生成输出始终使用规范顺序。

### 6.2 测试参数

`test=1` 只允许在启动解析时与合法 V1/V2 URL 共存，用于现有测试诊断。生成分享链接、二维码和 PNG 时必须删除 `test`。

## 7. 旧链接迁移

### 7.1 合法 V1

只含一个合法 `combo`，并可选一个 `test=1` 的链接视为旧版分享链接：

1. 通过现有组合 ID 恢复五件零件。
2. 调用 `createDefaultAffinityLayers(coreId)` 生成五层默认属性。
3. 返回 `legacyUrl: true`。
4. 显示一次提示：“旧版分享链接已按默认属性载入；重新分享可生成完整属性链接。”
5. 再次分享时输出 V2，不再生成 V1。

### 7.2 非法或未知版本

非法 V1、非法 V2 和未知未来版本均不猜测迁移，也不使用合法参数的子集。结果统一为：

- Storm Attack 零件。
- Storm Attack 默认属性。
- `invalidUrl: true`。
- 原有无效链接提示和“清除无效 URL”操作。

## 8. 启动解析和本地存档

启动解析返回完整结构：

- `combination`
- `affinities`
- `emblemId`
- `source: 'url' | 'local' | 'fallback'`
- `invalidUrl`
- `legacyUrl`
- `testMode`

优先级保持：合法 URL、合法本地存档、Storm Attack fallback。

- V2 URL：恢复 URL 零件、属性和可选纹章。
- V1 URL：恢复 URL 零件和默认属性，不读取本地属性。
- 无装配 URL：读取现有本地存档。
- 本地 V1：零件 + 默认属性。
- 本地 V2：零件 + 已保存属性。
- 本地存档永远不产生 `emblemId`。

分享 schema 升级不得改变 `combinationStorageKey` 或本地 `schemaVersion: 2`。

## 9. 分享会话纹章元数据

store 增加独立的 `shareEmblemId: string | null`，它不属于 `BuildSnapshot`。

行为固定如下：

- 合法 V2 URL hydrate：设置解析出的纹章 ID或 `null`。
- V1 URL、本地存档、fallback 或非法 URL hydrate：设为 `null`。
- 手动换件、改变属性、受约束随机、撤销和重做：保持当前纹章 ID，便于编辑后继续转发。
- Storm Attack 重置、恢复本地存档、导入 JSON 或从组合库恢复整套装配：清除纹章 ID，避免附着到另一套来源装配。
- `save()` 不写纹章 ID。
- `currentSnapshot()` 可暴露该会话值供 E2E 观察，但它不进入历史和战斗。

本阶段不提供纹章 UI；该字段仅服务协议连续性。

## 10. 分享输出

`createShareLink()` 改为接收当前完整基础装配和可选纹章 ID：

- 当前 `combination`
- 当前 `affinities`
- 当前 `shareEmblemId`
- 当前地址与可选公开 base URL

它必须：

1. 清除原地址的全部 query 和 hash。
2. 按固定顺序写入 V2 参数。
3. 只在纹章 ID 非空且合法时写 `emblem`；无效内部输入明确拒绝，不静默删除。
4. 不保留 `test=1` 或其他旧参数。
5. 保持现有 `deviceOnly` 判断。

App 的分享派生依赖零件、五层属性和会话纹章。因此只修改属性也会立即更新文本框、二维码和 PNG 使用的 URL。

## 11. 分享、二维码和 PNG

- 分享文本框显示 V2 URL。
- 复制按钮复制文本框同一字符串。
- 页面二维码使用同一字符串。
- PNG 装备卡二维码使用同一字符串。
- PNG 正文和文件名保持现状，不在本阶段增加属性徽章或纹章图像。
- 卡片输入校验除现有组合 ID 外，还应确认 URL 能解析为与当前零件和属性相同的 V2 基础装配。
- 导出前后不得改变零件、属性、相机或 3D 永久矩阵。

## 12. 错误处理

- URL 解析是纯函数，不抛出可由用户构造的格式错误；格式错误返回 fallback 与 `invalidUrl: true`。
- 生成器接收非法组合、属性或纹章属于编程错误，明确抛错。
- 未知未来版本不能回退为 V1。
- 非法 V2 不读取本地存档，避免恶意链接悄悄显示本地私有装配。
- 迁移提示和无效提示互斥；无效提示优先。
- QR 或 PNG 生成失败继续使用现有局部错误处理，不破坏当前装配。

## 13. 测试策略

### 13.1 单元测试

- 288 种组合的 V1 解析和 V2 往返。
- 七种属性在五个槽位中的编码与恢复。
- V2 参数固定顺序和重复生成确定性。
- 合法纹章、缺省纹章以及边界长度。
- 缺失、重复、额外、大小写、非法版本、非法属性、非法纹章和新旧混搭反例。
- V1 迁移标记与默认属性。
- V2、V1、本地 V2、本地 V1、fallback 的明确优先级。
- store hydrate 不创建历史并正确设置 `shareEmblemId`。
- 手动编辑/撤销保留纹章；重置、恢复、导入和组合库替换清除纹章。
- 分享载荷键集合证明不含流派、共鸣、概念属性和规则预设。
- PNG 卡片输入校验比较零件与五层属性。

### 13.2 端到端测试

- 设置非默认五层属性，打开分享面板，复制 V2 URL，在新页面完整恢复。
- 文本框、剪贴板和页面二维码内容一致。
- 带纹章的 V2 URL在再次分享时保留纹章。
- V1 URL显示迁移提示并输出 V2。
- 非法 V2 恢复默认装配、显示无效提示并可清除 URL。
- PNG 二维码解码为完整 V2 URL，解码后零件与属性等于导出前状态。
- desktop/mobile 均无新增 console error、page error、失败请求或外部请求。

## 14. 明确不变项

- 原有战斗和博弈模式不变。
- 七属性克制、共鸣和构筑流派评分不变。
- 本地存档 schema 仍为 V2。
- Arena 链接仍使用现有 `combo + loadoutVersion=1`。
- 规则预设仍只存在于当前定制器会话，不进入分享。
- 不新增纹章图片加载、上传或服务端请求。
