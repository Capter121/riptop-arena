# NSS 定制器构筑流派解释设计

日期：2026-08-02
状态：已批准，等待规格复审

## 1. 背景与目标

Web Customizer 已支持五层零件、七属性附加、共鸣结算和替换前后差值预览。本阶段为当前配装生成一个确定性的“构筑流派”解释，帮助玩家理解配装更接近持续进攻、防守、耐久、反击、属性爆发还是均衡发展。

构筑流派是只读说明，不提供额外属性，不修改现有博弈战斗，不替代玩家可主动切换的均衡、强袭和堡垒战术模式。现有战术倍率、七属性共鸣和未来阶段 3 的元素战斗接入保持各自独立。

## 2. 成功标准

- 每套合法配装稳定产生一个主流派，以及零至两个次级倾向。
- 支持强袭、堡垒、耐久、反击、爆裂、均衡六种解释标签。
- 判定只使用现有六项概念属性和已解析的属性共鸣，不按具体零件 ID 建立手工映射。
- 面板说明主要判定来源，并明确标注“仅作打法建议，不提供额外加成”。
- 更换零件或属性后流派同步更新，但不写入状态、历史、存储、分享或 Arena 参数。
- 六种固定样例、评分边界、组件展示、桌面和手机布局以及现有战斗黄金样例均通过验证。

## 3. 产品边界

### 3.1 本阶段实现

- 确定性构筑流派纯函数。
- 一个主流派、最多两个次级倾向。
- 主流派的数值来源解释。
- 定制器共鸣摘要下方的紧凑解释轨。

### 3.2 本阶段不实现

- 不给任何流派添加被动或条件战斗加成。
- 不根据流派自动切换战术模式。
- 不允许玩家手动选择或锁定流派。
- 不把流派写入 Zustand、撤销历史、本地存储、分享链接或 Arena 载荷。
- 不实现任务 2.4B 的规则预设、违规提示或受约束随机配装。
- 不修改概念属性、属性克制、共鸣、物理或伤害公式。

## 4. 输入与输出

新增共享纯函数模块 `battle-top-designer/shared/nss/build-profile.ts`。

输入：

- 六项现有概念属性：攻击、防御、持久、平衡、重量倾向、高度倾向。
- 现有 `resolveAffinityProfile()` 产生的 `AffinityProfile`。

输出：

- 一个稳定的主流派代码。
- 零至两个次级倾向代码。
- 主流派的结构化原因。

稳定代码固定为：

- `ASSAULT`
- `FORTRESS`
- `ENDURANCE`
- `COUNTER`
- `BURST`
- `BALANCED`

共享模块不依赖 React、DOM、Three.js、Zustand、存储或战斗运行时，也不包含定制器中文界面文案。

## 5. 确定性评分

六项概念属性使用现有 0–100 数值。每个候选分数保留两位小数后参与排序。

### 5.1 强袭

```text
attack × 0.60 + balance × 0.25 + weight × 0.15
```

表示高攻击、具备持续压制所需平衡，并有一定重量倾向的配装。

### 5.2 堡垒

```text
defense × 0.60 + weight × 0.25 + balance × 0.15
```

表示高防御、较强重量支撑和稳定承压能力。

### 5.3 耐久

```text
stamina × 0.65 + balance × 0.25 + defense × 0.10
```

表示以持久为核心，同时具备维持旋转所需的平衡和基础防御。

### 5.4 反击

只使用攻击、防御和平衡：

```text
minimum(attack, defense, balance) × 0.55
+ average(attack, defense, balance) × 0.45
```

最低项占较高权重，保证任一明显短板都会拉低反击评分，避免把纯防御配装判为反击。

### 5.5 爆裂

爆裂只由纯属性进攻共鸣激活：

| 同属性件数 | 爆裂分数 |
|---:|---:|
| 无进攻共鸣 | 不参与排名 |
| 3 | 68 |
| 4 | 84 |
| 5 | 100 |

爆裂表示属性集中爆发，不复制或扩大共鸣的实际战斗倍率。

### 5.6 均衡

先计算攻击、防御、持久、平衡四项的最大值与最小值之差 `spread`：

```text
clamp(78 - spread + harmonyBonus, 0, 100)
```

存在任意协调共鸣时 `harmonyBonus = 8`，否则为 0。重量和高度倾向不参与均衡离散度。

## 6. 排名与次级倾向

1. 参与排名的最高分为主流派。
2. 其他流派同时满足“分数至少 55”且“与最高分相差不超过 6”时成为次级候选。
3. 次级候选按分数降序排列，最多保留两个。
4. 完全同分使用固定顺序：爆裂、均衡、反击、耐久、堡垒、强袭。
5. 不使用随机数，不参考零件稀有度、解锁状态、强化等级或对手数据。

## 7. 原因解释

只有主流派显示详细原因，次级倾向只显示标签。最多显示三项来源：

- 强袭：攻击、平衡、重量倾向的原始数值。
- 堡垒：防御、重量倾向、平衡的原始数值。
- 耐久：持久、平衡、防御的原始数值。
- 反击：攻击、防御、平衡的原始数值，并说明最低项约束。
- 爆裂：主属性、同属性件数和现有元素进攻共鸣百分比。
- 均衡：四项最大差值；存在协调共鸣时显示现有防御和稳定性加成。

界面使用真实数值，例如“攻击 74 · 平衡 56 · 重量倾向 61”，不使用没有阈值定义的“很高”“略强”等模糊词。

## 8. UI 设计

采用已批准的方案 A：共鸣摘要下方的紧凑解释轨。

- 位置：`AffinityPanel` 正式共鸣摘要之后、下方概念属性与快捷工具区域之前。
- 标题：`构筑流派 · 仅作打法建议`。
- 主流派使用最强视觉层级。
- 次级倾向使用最多两个紧凑标签。
- 原因在同一轨道内显示，桌面横排，手机自然换行。
- 固定显示“不提供额外加成”，避免与 Arena 中可切换的强袭、堡垒战术模式混淆。
- 面板没有按钮、选择框或折叠操作，不制造可交互错觉。
- 不复制完整概念属性表和共鸣面板。

新增 `battle-top-designer/web-customizer/src/build/BuildProfilePanel.tsx`，负责把稳定代码和结构化原因转换为中文展示。

## 9. 数据流与状态边界

```text
当前五件零件
  → conceptAttributes()
  → 六项概念属性 ┐
                  ├→ resolveBuildProfile() → BuildProfilePanel
当前五层属性      │
  → affinityProfile ┘
```

- `App` 使用现有派生数据调用纯函数。
- 零件或属性变化时通过 `useMemo` 重新计算。
- 不新增 Zustand 字段或第二个 store。
- 不把派生流派加入撤销/重做快照。
- 不写入本地组合、分享链接、二维码、PNG 卡或 Arena URL。
- 后续需要在 Arena 展示时可重新调用共享纯函数，服务端和客户端均不接受外部提交的派生流派值。

## 10. 错误与边界处理

- 六项属性必须完整，并且每项都是 0–100 的有限数值；非法输入明确抛出错误，不截断、不补默认值。
- `AffinityProfile` 由现有共享解析器产生，不在流派模块复制七属性验证规则。
- 没有纯属性进攻共鸣时，爆裂从候选集合移除，而不是记为零分参与次级倾向。
- 次级倾向可以为零个或一个，不补占位标签。
- 相同输入必须得到相同排序、原因顺序和输出。
- 纯函数不得修改属性或属性档案输入。
- 定制器内部数据理论上始终合法；若计算意外失败，页面记录错误并隐藏流派解释轨，现有零件选择、属性选择和共鸣摘要继续可用。

## 11. 验证设计

### 11.1 纯函数测试

- 六种流派各有一个固定正例。
- 覆盖完全同分的固定裁决顺序。
- 覆盖次级倾向最低 55 分和距主流派最多 6 分的包含/排除边界。
- 覆盖爆裂 3、4、5 件以及无进攻共鸣。
- 覆盖协调共鸣增加均衡解释分，但不改变实际共鸣数据。
- 覆盖反击的最低项惩罚。
- 覆盖输入不可变、重复调用相等和非法属性拒绝。

### 11.2 组件测试

- 显示一个主流派和零至两个次级倾向。
- 显示主流派原因和固定免责声明。
- 不渲染评分公式或交互按钮。
- 失败或空结果时不渲染空面板。

### 11.3 浏览器与回归

- 更换零件后流派和原因同步更新。
- 更换附加属性、获得或失去进攻/协调共鸣后流派同步更新。
- 流派刷新不产生额外历史记录、模型加载或本地写入。
- 桌面和手机截图无裁切、覆盖或不可达内容。
- 浏览器控制台无新增错误。
- 现有定制器单元测试、TypeScript、生产构建和 desktop/mobile E2E 通过。
- 根项目战斗黄金样例通过，确认本阶段没有改变任何战斗倍率或伤害结果。
