# 私人服务器邀请码管理 CLI 设计

日期：2026-08-10

状态：设计已确认，待规格复核

## 1. 目标

为仅供受邀朋友使用的 NSS Arena 私人服务器补齐最小、安全的本地邀请码管理能力。管理员通过服务器终端创建、查看和停用邀请码，不新增公网管理 API 或管理页面。

成功标准：

- 空数据库可自动执行现有迁移并创建邀请码。
- 默认生成高强度、单次使用的邀请码。
- 可明确指定自定义邀请码和最大认领次数。
- 列表默认隐藏完整邀请码，只有 `--reveal` 才显示原值。
- 停用后拒绝新的身份认领，但不影响已经认领的玩家。
- 管理命令不会删除邀请码或玩家记录。
- 自动化测试覆盖 CLI、SQLite 持久化以及现有身份认领行为。
- 不改变战斗、挑战、进度、装配和门户流程。

## 2. 已确认的约束

- 采用单一脚本和 `create`、`list`、`disable` 三个子命令。
- 默认 `max_uses` 为 `1`，可通过 `--max-uses` 明确增加。
- 默认自动生成邀请码，也允许通过 `--code` 指定自定义值。
- 列表默认脱敏，只有显式 `--reveal` 才显示完整邀请码。
- CLI 只供拥有服务器文件和终端权限的管理员使用。
- 沿用现有 `invites` 表，不新增迁移。
- 停用只阻止新的认领；既有玩家身份继续有效。
- 不提供删除、重新启用、搜索、分页、JSON 输出、远程调用或网页后台。

## 3. 命令接口

脚本入口：

```text
node scripts/manage-invites.mjs <command> [options]
```

同时在 `package.json` 提供简短入口：

```text
npm run invite -- <command> [options]
```

具体命令：

```text
# 创建默认单次使用的随机邀请码
npm run invite -- create

# 创建最多可认领 5 次的随机邀请码
npm run invite -- create --max-uses 5

# 创建自定义邀请码
npm run invite -- create --code FRIENDS-2026 --max-uses 5

# 默认脱敏列出全部邀请码
npm run invite -- list

# 明确显示完整邀请码
npm run invite -- list --reveal

# 停用邀请码
npm run invite -- disable FRIENDS-2026
```

未知子命令、未知参数、缺少参数或不适用于当前子命令的参数均返回非零退出码，并打印简短用法。

## 4. 数据库与运行边界

CLI 复用项目现有的 SQLite 打开和迁移能力：

1. 从 `DATABASE_PATH` 读取数据库路径；未配置时沿用服务端当前默认路径。
2. 打开数据库并执行现有迁移。
3. 只对现有 `invites` 表执行参数化 SQL。
4. 无论成功或失败，都关闭数据库连接。

CLI 不调用网络接口，不引入管理员令牌，也不暴露新的 HTTP 路由。它不复制身份认领业务逻辑，现有 `invite-service` 继续作为玩家认领邀请码的唯一业务入口。

## 5. 创建邀请码

### 5.1 自动生成

未提供 `--code` 时，使用 Node.js `node:crypto` 生成：

```text
NSS-<20 位大写十六进制字符>
```

20 位十六进制字符来自 10 个随机字节，提供约 80 位随机强度。生成值满足现有数据库的 6–64 字符约束。

### 5.2 自定义邀请码

`--code` 必须同时满足：

- 长度为 6–64 个字符。
- 只包含 `A-Z`、`a-z`、`0-9`、`-` 和 `_`。
- 不接受首尾空白，也不静默裁剪。

自定义邀请码保持大小写敏感，与当前身份认领逻辑一致。新限制只约束通过本 CLI 创建的邀请码，不修改已有数据。

### 5.3 最大使用次数

`--max-uses` 默认值为 `1`。显式值必须是 JavaScript 安全整数范围内的正整数；零、负数、小数、非数字和超出安全整数范围的值均被拒绝。

### 5.4 写入与输出

创建使用单条参数化 `INSERT`。数据库主键约束负责最终防止重复邀请码。成功后输出：

- 本次创建的完整邀请码。
- 最大认领次数。
- 实际数据库路径。

完整邀请码只在创建成功时主动显示一次；后续列表仍默认脱敏。重复邀请码返回非零退出码，不修改已有记录。

## 6. 列出邀请码

`list` 查询全部邀请码，按 `created_at DESC` 排序，同时包含启用和停用记录。

输出字段：

```text
CODE  STATUS  USES  CREATED_AT
```

- `STATUS` 显示启用或停用状态。
- `USES` 显示为 `use_count/max_uses`。
- 默认邀请码仅保留前两位和后两位，中间字符替换为 `*`。
- `--reveal` 显示数据库中的完整邀请码。
- 没有记录时正常退出，并提示尚无邀请码。

列表不读取或输出玩家昵称、身份令牌及其他玩家数据。

## 7. 停用邀请码

`disable <code>` 使用精确邀请码执行参数化 `UPDATE`：

- 启用中的邀请码更新为 `enabled = 0`。
- 已停用的邀请码提示当前状态并正常退出，使操作保持幂等。
- 找不到邀请码时返回非零退出码。
- 成功输出只使用脱敏邀请码。

停用不会删除记录、降低使用次数或修改关联玩家。现有身份令牌继续有效；身份服务只在新的邀请码认领发生时检查 `enabled`。

## 8. 错误处理与输出安全

- 普通输入错误打印简洁说明和相关用法，不展示内部堆栈。
- 数据库打开、迁移或 SQL 失败时打印简洁错误，并返回非零退出码。
- 不吞掉异常；顶层负责将预期错误转换为管理员可理解的消息。
- 所有 SQL 使用参数绑定。
- `list` 和 `disable` 默认不泄露完整邀请码。
- `create` 的完整邀请码可能进入终端记录或部署日志；文档明确提醒管理员不要把命令输出发布到公共日志。

## 9. 自动化测试

测试使用临时 SQLite 数据库，并优先通过子进程执行真实 CLI，以验证参数解析、退出码、迁移、终端输出和数据库结果组成的完整行为。

覆盖以下场景：

1. 空数据库自动迁移并成功创建邀请码。
2. 默认创建 `max_uses = 1` 的随机邀请码。
3. 随机邀请码符合 `NSS-` 加 20 位大写十六进制字符的格式。
4. `--max-uses` 正确持久化。
5. 合法 `--code` 正确持久化。
6. 重复邀请码失败且不修改原记录。
7. 非法字符、非法长度和非法使用次数被拒绝。
8. `list` 默认脱敏且不包含完整邀请码。
9. `list --reveal` 显示完整邀请码。
10. 列表正确显示状态和使用次数。
11. 停用不存在的邀请码失败。
12. 重复停用保持幂等。
13. 停用后新的身份认领被拒绝。
14. 停用前已经认领的玩家身份仍有效。
15. 成功命令退出码为 `0`，输入或数据库错误返回非零值。

临时测试路径不得指向真实 `data/arena.sqlite`，测试清理只处理测试自己创建的明确文件。

## 12. 明确不做

- 邀请码管理 API 或管理网页。
- 管理员账户或远程管理员认证。
- 邀请码删除、恢复启用或自动过期。
- 批量创建、批量停用、导入或导出。
- 搜索、分页、排序参数或 JSON 输出。
- 改变身份令牌生命周期或撤销既有玩家身份。
- 改变战斗、挑战、装配、属性、进度或门户流程。
- 新增第三方依赖。

## 13. 风险与限制

- 自定义邀请码的强度由管理员负责，推荐优先使用自动生成值。
- `--reveal` 和创建成功输出会暴露完整邀请码，应只在可信终端执行。
- 数据库文件权限仍由部署环境负责；CLI 不替代操作系统访问控制。
- 本功能管理邀请码生命周期，但不提供既有玩家身份撤销能力。
